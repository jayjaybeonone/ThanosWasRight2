## Problem Statement

Calendar info is spread across several Google calendars, events carry stale details, and locations are sometimes wrong. Prepping for the day takes too long and the results still aren't good enough. The user wants one morning view that combines: weather, important meetings, local news, a sports recap, and commute time. Friends also want to check on their teams, so the view should be shareable with a group.

## What Makes This Cool

The calendar decides what matters. The briefing doesn't just list events. It says things like "leave by 8:12 for the 9am at the other building." A friend opens one link and sees how their team did last night, without installing anything.

## Constraints

- Learning / side project. No budget for hosting or paid APIs beyond small usage.
- The repo is mixed-purpose (an Android app, a Hue color page, gstack config). The feature needs its own directory and must not disturb the existing projects.
- There is no existing calendar, weather, news, or sports code in the repo. Everything is new.
- Calendar data is personal. Only the owner's calendar is read in this approach.

## Premises

1. The core value is one shared page where each person sees their own day (calendar, weather, commute) and their teams' news and results. The calendar is the spine. (Confirmed by user)
2. Each person connects their own Google Calendar with their own permission. Nobody sees anyone else's calendar unless they opt in. (Confirmed by user)
3. Team scores, news, and weather come from public APIs, not from anything friends type in. (Confirmed by user)
4. Commute time needs a maps/directions API, which has a usage cost. (Confirmed by user)
5. For a learning or side project, start with a static or lightly backed page, not a full app with accounts. (Confirmed by user)

## Approaches Considered

### Approach A: Scheduled static page (chosen)
A daily job pulls the owner's Google Calendar, weather, team results, and local news, then writes one static HTML page. The owner shares its link with the group. Effort S, risk low.

### Approach B: Per-person briefing with a light backend (deferred)
A small serverless app with Google sign-in for each friend, storing tokens and building each person's briefing. Rejected for now: the OAuth setup and token storage are most of the work, and the first version doesn't need per-person calendars. Revisit after the group uses version A.

### Approach C: Morning text or email digest, with the page as the archive (deferred)
Rejected for now: sending messages on behalf of friends needs their consent and carries spam risk. Revisit if people stop opening the page.

## Recommended Approach

Approach A. A scheduled job (GitHub Actions cron or a local cron) runs each morning and does four things:
1. Reads the owner's Google Calendars (read-only OAuth) and lists today's events across all of them, using the most recent event details.
2. Fetches weather, team results, and local news from public APIs.
3. Adds commute time last, using a directions API from the event location.
4. Writes one static HTML page, shared by link.

Friends see the team, news, and weather sections. The calendar section stays private to the owner in this version.

## Open Questions

- Which teams, and which city, should weather and local news use?
- Where should the page be hosted? A public GitHub Pages site would expose calendar summaries, so calendar content needs private hosting or should stay out of the shared page.
- Which news and sports APIs will be used, and do they need keys or have free-tier limits?
- For commute time: which travel mode, and where does the origin come from (home address, or the previous event's location)?

## Success Criteria

- The page regenerates automatically each morning for 5 consecutive weekdays.
- Meeting times and locations match Google Calendar for every calendar that is connected.
- A friend can find their team's last result in under 10 seconds of opening the link.
- Commute time appears for at least one in-person meeting per day, or is clearly marked as unavailable.

## Distribution Plan

The page is a static HTML file, shared by link. The daily build runs on a scheduled GitHub Actions workflow or a local cron. No app store or package release is needed.

## Dependencies

- A Google Cloud project with the Google Calendar API enabled and OAuth credentials.
- API keys for weather, news, sports, and directions. Check each provider's free tier before building.
- Decision on private hosting for any page that shows calendar content.

## Next Steps

1. A read-only script that lists the owner's calendars and today's events.
2. Add the weather and team-results fetchers, each writing to a simple data file.
3. Render the daily HTML page from those data files.
4. Schedule the daily job.
5. Add commute time last, once the rest works.
